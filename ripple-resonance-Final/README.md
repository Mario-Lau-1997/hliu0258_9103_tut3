# Ripple: Resonance — Stage 3: Scene files and sound

All stage 2 controls, plus validated JSON scene files, comparison examples and an optional audio mechanic.

This refreshed set uses the same supplied painted background in all three stages.
Later stages keep the earlier features. These are source snapshots, not a replacement
for the commit history in a repository.

## Run locally

Extract the complete folder and open `index.html` in a desktop browser. Keep the
`js`, `assets` and `vendor` folders beside it. No server or internet connection is
needed to run the artwork. Node and Playwright are used only for development tests.

## Concept

Separate actions form one shared pattern. Each wave source contributes to a common
field. Moving a source, reversing its phase or changing its strength affects the
combined contours and the paths of particles. The user-input mechanic is the main
interaction. Seeded Perlin drift supports the visual movement. A water-like audio
track and short interaction sounds also change the strength of the shared wave field.

The painted water image is a fixed background. Its painted ripples are different
from the wave contours generated by the code. The picture is scaled proportionally
to cover the canvas; different window shapes crop its edges without stretching it.
`assets/water-reflections.png` preserves the supplied image bytes. An embedded copy
in `assets/background-image.js` allows offline loading and PNG export.

## Sound

Click **Enable sound** to start. The page is silent until you choose this. The
24-second loop combines a soft noise texture with small synthetic water drops.
Add or move a source to hear another drop. A source on the left sounds further
left; a source on the right sounds further right. Reversing phase gives a lower,
falling tone. These sounds are artistic cues, not measurements of real water.

The **Sound → wave strength** meter shows the response. Louder moments make the
generated wave field slightly stronger, up to 30%. The loop and live drops both
contribute. The painting itself stays fixed. Pause stops audio and animation;
Resume continues them. Loading a scene also pauses both. Sound pauses while the
browser tab is hidden. Reduced-motion mode starts paused: enable sound, then
choose Resume when ready. Mute and volume zero are always available.

The WAV and an embedded copy are included, so playback does not need a server,
internet connection or microphone. Sound settings apply only to this session.
JSON files save scene settings; PNG files save still images. Neither export saves
audio playback. Use a screen recorder with system audio if you need a video.

## How the code works

The field adds damped radial sine waves. Each source has a normalised position,
strength, phase and ID. Opposite phases can cancel; equal phases can reinforce.
The wave model is an artistic simplification, not a physical water simulation.
The field is sampled on a bounded grid. Marching squares finds contour crossings,
and interpolation gives particles values between grid points. Particles follow
a rotated field gradient plus smooth noise. A transparent buffer stores fading
trails. Both contours and particles read the same field.

`sketch.js` owns the scene inside a p5 instance. The field owns source objects;
the input controller owns the current selection and active pointer ID. Temporary
values such as distance, gradient and pointer position stay within their methods.
The UI sends actions to those objects instead of keeping a second copy of the
artwork data. Resizing preserves normalised source positions and rebuilds the grid
and particle buffer. The canvas uses pixel density 1, up to 150 × 110 grid cells
and no more than 1,500 particles.

### Audio data flow

`audio-mechanic.js` owns one Web Audio context. The loop and oscillator drops pass
through gain controls, then an analyser, then the speakers. The analyser samples
the actual output waveform with `getFloatTimeDomainData()` (MDN contributors,
n.d.-a). The RMS level is the square root of the mean of the squared samples.

The mapping is `target = clamp(RMS × 45, 0, 1)`. A short smoothing step reduces
sudden changes. The final multiplier is `1 + 0.30 × smoothedLevel`. `sketch.js`
passes that value to `WaveField.audioBoost` before the field grid is updated.
Contours and particles therefore share the same response. A common multiplier
keeps equal opposite sources able to cancel. Source amplitude values and undo
history are not overwritten by the temporary audio response.

`InputController` sends add and move events to the sound module. `ArtworkUI`
sends phase, volume and enable events. Drop sounds use short gain envelopes;
drag sounds are spaced at least 120 ms apart and at most six voices can overlap.
The audio context is created only after a user action, following browser audio
practice (MDN contributors, n.d.-b). Unsupported audio leaves visual editing usable.

## Testing

Run `node --test tests/*.test.cjs` for the logic checks. To run the browser checks,
install Playwright and set `NODE_PATH` and `BROWSER_EXECUTABLE` as described at the
top of `tests/browser.cjs`; then run `node tests/revisions.cjs` and `node tests/audio-browser.cjs`. Current run results
are in `docs/`. They record automated checks, not a classroom user study.

## Limits

The image is 554 × 554 pixels, so it may look softer on large screens. The program
uses one fixed painting in every scene. Source controls change the generated layer,
not the painted marks. Testing in one browser does not establish compatibility with
all hardware. Audio output depends on the browser and system volume. There is no microphone input.
The audio tests check decoded samples and playback state; they do not claim a human
listening test on physical speakers. Before presenting, enable sound on your own
device and check its volume.

Undo restores settings, not old trail pixels. It restarts trails and keeps the current animation time. Pause before comparing edits. History is held only for the current page session.

Scene files keep layout and settings, not animation time or particle pixels. They load paused at time zero. Invalid files leave the current settings unchanged. The two files in `examples/` compare generated reinforcement and cancellation; the painting remains visible in both.
